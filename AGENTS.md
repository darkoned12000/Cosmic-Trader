# AGENTS.md -- Cosmic Trader (Flutter)

## Project at a glance

Flutter app targeting Android, iOS, web, Linux, macOS, Windows. Dart SDK ^3.6.2.
The Flutter project lives at the **repo root** (package name `cosmic_trader`).

## Commands (run from the repo root)

| Task | Command |
|------|---------|
| Get dependencies | `flutter pub get` |
| Run (device/emulator) | `flutter run` |
| Run on web | `flutter run -d chrome` |
| Run on Linux | `flutter run -d linux` |
| Analyze / lint | `flutter analyze` |
| Format check | `dart format --set-exit-if-changed lib/ test/` |
| Format fix | `dart format lib/ test/` |
| Run tests | `flutter test` |
| Single test | `flutter test test/widget_test.dart` |
| Clean + rebuild | `flutter clean && flutter pub get && flutter run` |

Always run `flutter pub get` before build, analyze, or test commands.

## Design docs
A design doc moves from the repo root into `docs/` once its work is **complete**. Anything still at
the root is in progress, so the root is the workspace and `docs/` is the archive of finished design
work. When a doc moves, update the pointers to it — `README.md` links and the list below — because
a stale path is worse than no path. Prose citations inside another doc (`§13.1 of
player-avatar.md`) name the document rather than linking it, so those need no change.

**In progress, at the root:**
- `planets.md` — Planet system design (types/atmospheres, colonies, Citadel levels 1-6, homeworld
  NPC repopulation, invasion mechanics, image pools, 6-phase implementation plan). Its "Current
  State" section tracks what has been implemented so far (phase 1 mostly done; colony automation
  and invasion combat outstanding).
- `faction-lore-update.md` — Narrative/lore expansion. Adds a unifying mystery ("The Fracture",
  Cycle 435) to tie the three playable factions into a shared history, replacing the current
  Empire-vs-Mystics-vs-Merchants archetype framing.
- `citadel-info.md` — **Reference and open design brief for planet levelling**,
  written to be handed to another model for review. Deliberately split into six
  parts so a reviewer cannot mistake an opinion for a rule: **Part I** is verified
  ground truth (tiers, costs, build time, what a tier grants, the production
  triangle, all ten class tables, storage, the supply bill, known gaps) and every
  figure is checkable against the file named in the header; **Part II** is opinion
  with evidence attached; **Part III** is the derived rules a proposal must not
  undo; **Part IV** is what already exists to build on — the one a reviewer is
  least likely to find unaided, including the finding that **invasion combat is
  nearly built already** because `PortDefenseConfig` + `PortCombatService` give a
  working 0–4 turn-based defence system whose defender stat lookup is a pure
  function of an int, which is exactly what `Planet.levelDefense` already is;
  **Part V** is twelve numbered questions to answer; **Part VI** records why the
  document is split. **It also warns that there are two citadel systems and only
  one is live** — `planet_classes.dart` holds a dead, sourced `citadelAbilities`
  table describing six classic TradeWars abilities nothing reads.

**Complete, in `docs/`:**
- `docs/player-avatar.md` — Player avatar system design. **Art direction is settled: portraits are
  generated by a deterministic `CustomPainter`, not drawn as assets** — the original "commission art"
  constraint was reversed on cost grounds, and §2 of the doc records the accepted trade (quality
  ceiling for combinatorial variety and zero asset maintenance) plus the quality bar every visual
  change is held to. Phases 1-4 and 6 are done; the customisation layer is complete (axes,
  backdrops, tabbed editor, per-axis reset, per-axis locks); uploads (phase 5) deferred by choice.
  The standing art bar is higher for NPCs than for the player, because nobody chose their face —
  re-run the sweep after any species-art change.
- `docs/hack-port-update.md` — Hack Port mini-game design (phases 1-3 shipped: security profiles,
  hardened two-stage ports, extraction choices, per-port bans, persistent Hack Codex).
- `docs/cosmic-trader-update.md` — Whole-gameplay review covering mechanics, look & feel, and NPC
  AI; the source of the A2 shared-widget library and A3 look & feel waves.

                                     `GameSettings.worldTick` on a 60-tick throttle;
                                     advanced by exactly ONE caller (GameTickService)
                                     before anything in a tick reads a deadline.
                                     Use it for every game duration — there is no second
                                     clock, and `DateTime.now()` in a gameplay path is a
                                     bug even when it looks right

      trade_evaluator.dart        -- TradeRoute evaluation, profit-per-hop analysis, nearest-port BFS, affordability + cooldown filters
      pathfinding_service.dart    -- BFS shortest path between sectors (id-keyed lookup)
      combat_service.dart         -- combat resolution engine, damage/loot/faction-standing calculation, siege estimate, CombatOutcome contract, morale (trigger/eligibility/resolution)
      port_combat_service.dart    -- port combat resolution engine (shared siege core) with defense stats

### Universe generator algorithm

`UniverseGenerator.generate()` runs 8 phases:

1. **Init** — Greek/mythological sector names, placeholder coords, empty warp lists. Also generates NPC ships via `_createNpcs()`
2. **Terra Prime** — Sector 1 gets a Federal port with random pricing via `_createPort`
3. **NavHaz/Anomaly** — 15% navHaz + anomalies at `anomalyDensity` outside FedSpace
4. **FedSpace hub** — Sectors 1-7 connect 2-3 peers; 8..fedEnd connect to 2-3 hubs
5. **General warps** — "grow-from-center" coords with bubble clustering; distance-weighted connections
6. **Orphan/connectivity/balancing** — Fix orphans, BFS repair, `_balanceDistribution` up to 100 iterations
7. **Ports** — FedSpace = Federal; outside = portDensity (30% federal, 40% free, 30% independent). Type strings are generated dynamically for the number of configured commodities. Each port gets defenseLevel (0-4), portCredits, ~40% chance of NPC owner; hardware emporium flag at hardwareEmporiumDensity
8. **Planets/NPCs** — Planet placement at planetDensity with per-type GIF images; a homeworld per major faction (duran/vinari/trader — preferred types, unique names, NPC spawn fields); NPCs by per-faction density settings (trader/duran/vinari/pirate). Aliens are not currently generated (only producer comments + a lore mention reference them)

Seeding: `GameSettings.seed` → `Random(seed)`. Seed 0 → time-based replacement.

### Economy model

Data-driven commodity system via `CommodityConfig` + `CommodityRegistry` (single source of truth in `commodity.dart`).
Adding a commodity requires just 2 entries in `commodity.dart` (+ mirror in `defaultsMap`).

Eight goods: minerals, organics, industrial, food, ore, crystalline, munitions, contraband.
Each commodity has a `[priceMin, priceMax]` range split at the mid-point (`splitPoint`):
- **Sell price** (player buys from port) = random in `[priceMin, splitPoint)` — lower half
- **Buy price** (player sells to port) = random in `[splitPoint, priceMax]` — upper half

Base prices **guarantee** `maxSellPrice < minBuyPrice`, but live effective prices layer cash-ratio × supply/demand depth × drift × regional/anomaly × standing (capped [0.25, 4.0] on the multiplier), so near-split routes can invert into real (logged, self-correcting) losses.

Ports use dynamic type strings (N characters, one per commodity). Each character = `S` (port sells, player buys), `B` (port buys, player sells), or `X` (untraded — contraband at law-abiding ports, padding on old saves). Generated at port-creation time with at least one `S` and one `B` among legal goods.

A port never buys and sells the same commodity. Contraband trades only at free/independent black-market ports (~30%).

Current defaults (editable in the Settings → Commodity Economy section):
- Minerals: 10-75 cr, 10,000-80,000 qty
- Organics: 80-150 cr, 5,000-70,000 qty
- Industrial: 160-300 cr, 3,000-60,000 qty
- Food: 5-40 cr, 8,000-60,000 qty
- Ore: 30-120 cr, 6,000-50,000 qty
- Crystalline: 200-450 cr, 1,000-8,000 qty
- Munitions: 150-400 cr, 2,000-15,000 qty
- Contraband: 300-800 cr, 500-5,000 qty

### NPC AI engine

Autonomous NPCs with 12 personality archetypes (3 per faction) across 4 factions (Duran, Vinari, Trader, Pirate). Goal state machine with weighted random selection (null-instantiating picks are skipped, not stalling):

- **Goals**: tradeRoute (incl. sell-first for full/nib holds), explore, attack, bankDeposit, bankWithdraw, patrol (5-leg expiry), flee, upgradeEquipment (repairs + levels + arrays), raidPort (siege-gated), refuelEnergy (discovered emporiums only), buyPort
- **Guards**: banking/distress/refuel only preempt interruptible (explore/patrol/none) goals; refuel breaks committed legs below 10%; dead goals never steer movement; failed routes cool 5 min
- **Personality config**: aggression (0-1), greed (0-1), caution (0-1), explorationDrive, maxTravelDistance
- **Pathfinding**: BFS shortest path via `PathfindingService` (id-keyed)
- **Trading**: Port discovery, profit-per-hop route evaluation (affordability + cooldown + standing aware), buy/sell commodities, bank profits
- **Banking**: Autonomous deposit/withdraw based on caution thresholds and credit balances; Guild interest for NPCs and players
- **Combat**: NPCs hunt hostiles (greedy prefer bounties), raid beaten ports, attack players (aggression + power + fear/hatred calculus)
- **Fear/hatred**: Notoriety inflates perceived power (deterrence + sector-clearing); standing ≤ −50 substitutes for hostility at 1.5× odds
- **Distress signals**: Outmatched NPCs broadcast; max 3 armed responders with trip budgets; en-route revalidation
- **Port owners**: NPCs buy unowned ports, collect revenue, upgrade defenses/storage; ownership keyed by stable id
- **Death cries**: Faction-specific broadcasts when NPCs are destroyed
- **Repopulation**: Homeworld control-gated respawns (extinction reversible)
- **Processing**: `GameTickService` (adjustable interval, re-entrancy guard, per-NPC error bulkhead, Fed bounties, NPC interest) batches NPC turns, proximity-filters events to player sectors
- **Player-visible logging**: NPC events reach the player's action log only from within 2 hops (`NpcAiService.playerProximitySectors`, set by `beginTick`). Everything still reaches `GameEventLog` at any distance, so gating never loses an event — it files it as world news instead of as something you watched. Unset (tests, direct `processTurn`) means no filtering

### Planet system (partially implemented — see `planets.md`)

- **Model**: 10 planet types (Terran/Jungle/Mountain/Desert/Ocean/Ice/Lava/Moon/Barren/Toxic), each with atmosphere, production multipliers, colonist max, and a pool of 3 animated GIF images. Gas Giant was **removed**: its source ratios are N-A on all three products, so it produced nothing at any staffing or Citadel level, still charged resources per build, and held 1 of 3 sector slots. 1 of 20 generator slots and 1 in 11 torpedo rolls

- **Levels**: 6 Citadel tiers (Outpost → Settlement → Colony → Fortified Colony → Planetary Base → Citadel) gated by colonists (a minimum, not a cost) + stored resources (consumed at build start). ## State management

No BLoC/Provider/Riverpod. Callback-driven lifted state in `GameShell`:

- Tab indices: 0=Sector, 1=GalaxyMap, 2=Ship, 3=Computer, 4=Port, 5=Planet, 6=Settings (7 views total)

- Theme via `ValueNotifier`s on `ThemeService` (color, brightness, font family, font size)
- `ActionLogProvider.global` — `ChangeNotifier` singleton for game event log (max 200 entries)

## Economy notes

The buy/sell price model creates a guaranteed profitable spread at every port — sell prices (player buys) are always in `[priceMin, splitPoint)` and buy prices (player receives) in `[splitPoint, priceMax]`. With current defaults (minerals 10-75, organics 80-150, industrial 160-300), a typical trade run nets 30-300%+ return. Players can also edit every range (price and quantity) in Settings → Commodity Economy.

- **A guard that cannot fail is worse than no guard.** `test/avatar_outfit_render_test.dart` has six pixel-sampling guards, each verified by injecting the fault it exists to catch: multi-tone torso (garment off-canvas), backdrops distinct and none-is-the-bloom (an index falling through to the default case), appendages-outside-the-head-clip (the original layer-order bug, re-injected by moving `appendages` back inside `clipPath`), the two-part Vinari silhouette guard described above (re-injected twice — once with the axis made inert, once with the frill's apex pushed back below the crown), and the per-species scowl floor (re-injected three ways — with the Terran override ignoring the Scowl, with the scowl disabled globally, and with the mouth curve flattened). When comparing renders, hold the *style* constant and vary only the axis under test, or the comparison silently tests something else.
- **Widget tests have two measurement traps.** (1) The default test font renders every glyph as a full-width box, so text measures ~2× too wide — an assertion that the six-tab editor strip fits a 430px phone "failed" by 90px and looked like a real layout bug; `test/avatar_designer_test.dart` loads the bundled `Audiowide.ttf` with `FontLoader` (inside `tester.runAsync`, or the load never completes) before asserting anything about fit. Related: **a tap on an off-screen widget silently does nothing** in `flutter_test` (it warns and moves on), so a test that taps a tab must assert the *content* changed, or scroll the target into view first.
- **Derive option counts from the list that supplies them, never from a shared constant.** `AvatarStyle.toneCount` is 6, but every dye list and the garment list hold 3. Generating colour options by looping to `toneCount` threw a `RangeError` *while building the row*, so the Face tab rendered one axis and then nothing — invisible to every test, found only by screenshotting the editor. `test/avatar_axis_catalog_test.dart` pins each axis's count against its source for the same reason.
- **`AvatarStyle.copyWith` cannot clear a nullable slot.** It resolves `?? this.x`, so `copyWith(eyeColor: null)` keeps the old value. Any "return this axis to its seed" path must use the explicit `clearEyeColor` / `clearBackdrop` / … flags, or the Reset button silently does nothing on every colour slot (whose seeds are all `null`).
- **Per-axis locks are transient by design and must stay out of the schema.** They describe how a player wants to re-roll, not what their pilot is, and are spent at Save. `AxisStyleAxis` lives in `lib/data/models/avatar_selection.dart` rather than beside the editor UI so `AvatarStyle.rerolled` can honour locks without the data layer importing widgets. `rerolled` rolls from the **current** style, not from neutral, because a lock has nothing to hold otherwise — with no locks the two are indistinguishable. `test/avatar_selection_test.dart` asserts the style's JSON stays a flat set of ints with no lock key.
- **Never assert a random outcome in a test.** "After a random re-roll this axis should differ from its seed" is true 3 times in 4 for a 3-option axis, and produced three separate flaky tests. Use a **forced generator** — `int nextInt(int max) => max - 1` against a base whose every axis is `0` — so anything that gets rolled is guaranteed to differ. Also note `pumpWidget` with an identical widget tree **reuses the existing `State`**, so a test asserting "this does not survive reopening" must pump something else in between to actually destroy it.
- **A layout that collapses does not overflow, and nothing will tell you.** Adding a 28px portrait to the faction-rankings Top 10 row squeezed the name column to ~4px at 430px width. `Expanded` absorbed the shortfall, so there was no `RenderFlex` overflow and no test failed — but every name then rendered one character per line and each card grew to ~200px. Only a 430px screenshot showed it. The guard **measures** instead: the name `Text` must be >80px wide *and* <40px tall, and the height is the half that matters, because a collapsed column is a *wrapping*, not an overflow. Use a deliberately long name in the fixture — a short one survives the squeeze by luck. Fixed with a `LayoutBuilder` fallback to one column.
- **A missing `path_provider` in a widget test hangs; it does not throw.** Driving `FactionRankingsScreen` needed `PlayerStorage`/`NpcStorage` fakes (both constructors were private, so a subclass could not be declared at all) and a `BountyBoard` whose `ensureLoaded` awaits `BountyStorage`. That await is left **pending** inside the fake-async zone, so the screen sat on its spinner forever and the test passed with nothing rendered. `BountyBoard.skipDiskLoadForTest` exists for exactly this. Whenever a screen loads in `initState`, check what it awaits before assuming a fake is enough.
- **Re-read your own edit; a fix can quote numbers for code you did not write.** A pirate-trim fix aimed at contrast against the *pirate's own cloth* kept `final base = outfit(species, variant)` — which resolves at the **default native affiliation**. The pirate branch therefore computed exactly what the native branch computed, and pirate trim came out **bit-for-bit identical** to native trim. The comment described a derivation the code did not do, the "never brighter" assertion passed because it was `lessThanOrEqualTo` and they were *equal*, and the render looked fine. A peer review spotted the assertion's weakness; re-reading my own edit found the cause. A described fix is not a checked fix: after any change, read the line you believe you changed.
- **Assert the property a viewer can see, not a relationship between two values from the same input.** A trim-vs-trim comparison cannot detect a trim that is invisible on its own cloth, and it cannot detect a trim that never varied at all. Both need their own assertion, and the second needs a *strict* inequality — `lessThanOrEqualTo` let "identical" through. The weak assertions were kept alongside the strong ones because they still catch a sign flip, and the comment now says exactly which failure each one is for.
- **A confounded measurement may be unable to see the thing it is named after.** The scowl guard compared a pirate face to a native one, which also picks up cloth, hair dye, and a Vinari face wash drawn in the hair colour: the Vinari's *background* difference was 3736 pixels against a scowl contribution of ~95, so an entire scowl removed from the Vinari still read far above the floor. The comment pointed at another file for cover — but that file asserts properties of a value object and never renders, so it could not tell whether a species' `expression()` consumed it. **A gap documented as covered is worse than an open one.** Fixed with an `AvatarDrawContext.scowlOverride` seam: render the same pirate twice, once with the scowl forced off, so the confound disappears for all three species (the smallest measurement rose from "unmeasurable" to 184).
- **A clamp with two bounds needs both halves argued for, and the wrong one is silent.** The emporium wrote `(held + sign).clamp(0, held)` to stop a *return* taking more than was carried. The upper bound of `held` also clamps `held + 1` straight back down to `held`, so buying from empty cost credits and changed nothing: the button worked, the money left, and the count never moved. It passed `flutter analyze`, formatted clean, read correctly, and had **no test at all**. A single pass over a clamp asks "is the floor right?" and stops; this one needed "what does the ceiling do to an *increment*?"
- **A test that reimplements the code under test proves nothing about it.** The first `test/emporium_ordnance_test.dart` built a harness with its own copy of the purchase logic, so it would have kept passing if the real widget went back to the broken clamp. A test copy is a second implementation, and the only thing it vouches for is that *it* is correct. Fixed by making the tab public (`EmporiumConsumablesTab`) and driving it directly.
- **A test host that does not rebuild what it hosts cannot see a second interaction.** The real tab is stateless and reports through a callback; the game satisfies that by `setState`-ing in `GameShell`. The first host passed the player in once and mutated a local, so a second purchase re-read a stale player and the guard failed for a reason unrelated to the bug. Every test then opened with `var live = pilot(...)`, **shadowing** the shared field with a local nothing wrote, so all the purchase assertions read a stale copy and reported 0 while the widget was working perfectly.
- **`find.byIcon` finds the Icon, not the button that holds it.** Casting the result to `IconButton` throws a `_TypeError` rather than failing an assertion, so the guard reported an exception and no verdict. Use `find.widgetWithIcon(IconButton, ...)`.
- **A getter that advances state cannot be used for display, and no assertion on the displayed number will notice.** The per-tick production getters consume the fractional remainder so that a colony yielding 0.03 units a tick eventually banks something. The colony card read them to show `+X/tick`, so *looking at a planet* banked its production early. Re-pointing them at the non-consuming per-day figure made **every test in the suite pass** while the bug was fully present \u2014 the number displayed was correct, and what was broken was a side effect. - **Measure the object the code touches.** The first version of that guard pumped the screen and compared the *fixture's* remainder, and passed against the injected fault every time \u2014 because the screen loads its own planet copy from disk and never touches the fixture. That is the two-copies problem reaching a guard: the test looked at the wrong object and its green told us nothing.
- **Two units, two ratios, and a divisor cannot be mixed.** A guard divided a per-day supply bill by a sum of per-tick getters \u2014 2,880x too large, and `Infinity` for any colony small enough to round to zero per tick. The test was asserting a share while measuring a different quantity entirely.
- **Reconstruct a rule from its outputs and the transcription stops being able to drift.** The TradeWars planet tables list `Max Production of Product` per class, and every one of those figures is `(maxColonists / 2) / ratio` — computed, not stated. Encoding the rule rather than the numbers means a single mistyped digit in one class breaks four independent assertions, because a wrong input shows up as a broken *relationship* rather than as a plausible number. It also gave the fighter economy for free: dividing the sum of a class's outputs by one per-class constant reproduced all seven published fighter ceilings, which is why the cap is derived and not a hardcoded 1,002.
- **One mechanic, two symptoms.** Production caps and the fighter ceiling are usually designed as two features that must be kept in sync. Here they are the same triangle: fighters come from output, so capping output caps fleets, and overstaffing a track past its peak lowers both. A second rule that has to be balanced against the first is a second thing to get wrong.
- **A rule with no caller is not a rule, and its tests cannot tell you.** `WorldForging.runDailyCollisions` was implemented, fully tested, and called from nowhere in `lib/` — so over-stacking warned about a hazard that could not happen, and its tests passed *because* they call the rule directly, which is how they reach it. Fixed by driving it from `GameTickService` (which already loads fresh sectors, has a timestamp and an RNG) and by `test/gravity_wiring_test.dart`, a **source scan** for exactly that question. The scan is a documented exception: a full tick fixture is a large thing for a one-line question, and only a scan asks "is there a call site".
- **A source scan is answered by prose, so do not use one to test behaviour.** That same guard checked the panel's source for `UNSTABLE` to assert the over-stack warning was gone — and failed, because the *comment explaining the removal* still contained the word. Source scans are for structural facts (does X call Y) and nothing else. The warning check is a widget test that taps the control and watches; a comment cannot answer it.
- **A row that goes through select-then-act needs a button in the act state.** The Genesis Torpedo entry was appended to the sector panel and the launch wired into the handler, but `_interactionButtons` returned `SizedBox.shrink()` for it — so the row could be selected and then showed *no way to fire*. Bought, carried, unreachable. Every layer was individually correct and the gap was one missing widget between them. The guard taps SELECT, asserts the button appears, taps it, and asserts the world count changed.
- **A mutable field cannot be a constructor parameter.** `Sector.destabilisedAtMs` is a plain `int?` on the class body because it arms and clears as the sector crosses the cap, so `fromJson` builds the sector and assigns afterwards rather than passing a parameter that cannot exist.
- **A clock is per holder, and re-arms or it is a trap door.** The gravity clock starts when a sector goes over the cap, so the due check asks "is that stamp 24h old" and never "is it 3am" — a global wall-clock hour would destroy worlds in a system that had been unstable for three minutes. A surviving check re-arms from the moment it came due; without that, a player who survives the first roll has a permanently safe over-stacked system and over-stacking stops being a decision. `reconcileStability` clears it when the sector comes back under the cap, so the detonator actually cancels the hazard.
- **A control can be duplicated and the copy be worse than the original.** A colony track row carried a `−` on *both* sides of its count, and both pulled colonists off the track — but the leading one was enabled only when the track held a full step, so on any colony smaller than a step it rendered greyed out and read as a dead control. Asked directly, nobody could say what either button did. A bare `+/−` pair on a row of numbers also does not say that it *moves colonists between two places*, so each button now has a tooltip naming its source or destination, and the card spells it out in prose.
- **`Semantics` without `container: true` does not create a node — it annotates one.** The requirement labels on the level gate were written, unit-tested, and completely invisible to `find.bySemanticsLabel`, because the default `container: false` merges the label into the nearest ancestor, where a screen reader reads the whole card as one run of text. The first guard asserted the `Semantics` *widget* carried a label and passed while the tree could not see it. The guard now walks the tree and asserts a standalone node per requirement, and `container: true` is the fix. Note the tree walk needs the **deprecated** `tester.binding.pipelineOwner` — the modern `rootPipelineOwner` is empty under `testWidgets` and reads as "the screen has no semantics" rather than as a failure.
- **A finder that happens to be unique is a finder that will silently find the wrong thing later.** `find.byType(Tooltip)` was unique until the workforce steppers were tooltipped too, at which point it threw "Too many elements". Scoped to the tooltip it means by its content.
- **Equipment is not cargo, and a zero constant is not a fix.** The torpedo was first built cargo-bounded via `cargoUsed ± cargoPerUnit`, which was a no-op only because the constant was 0 — an accounting accident waiting for someone to retune it. The rule is now stated by the *absence* of the line, with a guard that fires if it reappears.
- **A guard duplicated into a handler is a guard that can disagree with its button.** The emporium's buy handler carried `if (player.credits < 0) return` — dead, and wrong (a pilot with no credits is not negative), while the button had already refused. Checks live on the control.
- **Two predicates for two questions.** `Sector.isFull(cap)` (`>=`, the pre-launch question) and `isOverStacking(cap)` (`>`, the state the collision roll acts on) are deliberately separate. Conflating them called a sector holding exactly its cap "gravitationally unstable", and a guard that asserted the distinction then passed against a fault.
- **A fixture that satisfies the condition it is testing proves nothing.** The collision guard used three living worlds against a cap of three - exactly *at* the cap, where the roll correctly declines to act - so the loop did nothing and the test passed on an assertion it should have failed. Over-stacking needs four.
- **A counter that can desync should clamp.** Detaching a detonator decremented `cargoUsed` with no floor, and a negative hold is a nonsense figure on the HUD that then becomes the space budget for every later purchase.
- **A numeric bound that is not derived from its fixture outlives it.** The workforce-stepper guard asserted `greaterThan(100)` when the fixture started at 100 colonists, then the fixture was changed to start at 950 and the bound was left behind — so it passed with the button dead. - **Two writers with a read-modify-write each will silently erase each other, and the window is the whole pass.** `GameTickService` loads the whole universe, runs the NPC pass over the roster (seconds of BFS-heavy work at scale), then writes that snapshot back. `PlanetScreen` loads its own copy, mutates it, and writes. A recruit landing inside the tick's load→save window is overwritten by a copy taken before it existed — no error, no log, and indistinguishable from the feature never having worked. Reproduced in `test/concurrent_write_clobber_test.dart`. **And if a pass takes longer than its own interval it is not a race at all:** `processTickNow` skips overlapping fires, so a tick that never finishes never sleeps, and *every* screen write is clobbered. That is the likeliest explanation for a 100% failure rate where a race predicts an intermittent one — so when a concurrency bug reports as "always", **measure the writer's duration before assuming a probability**. So: the write fails quietly → `setState` never runs → the 1-second `_syncFromDisk` re-reads the *un-persisted* universe → the purchase is reverted within a second, with no error anywhere. - **A gate listing "things the tick might have changed" is not a save, and it hides its own failures.** The tick wrote the universe only when `portsRegened > 0 || processed > 0 || collided > 0`. A colonist shipment's **countdown** was not on that list, so it was never persisted, reloaded as full, decremented, and thrown away — every tick. The shipment could therefore **never arrive at all**, silently, forever. Worse, the gate made it look like an optimisation while behaving like a coin flip: `processed > 0` is true on any populated galaxy, so it saved by luck nearly every tick and only failed when the roster was empty. The gate is gone; the tick now saves unconditionally, and one JSON write per 30s is not worth a correctness bug. The `collided` term had been bolted onto the same line for the same class of bug (a collision announced but resurrected on the next load), so the pattern had already failed once before the second instance was added.
- **A counter that is never persisted is not a countdown.** The lesson above generalises: anything the tick derives per-pass and must *carry* — sub-unit production remainder, `Port.regenRemainder`, a transit countdown, `supplyTimer` — has to survive the reload that happens at the top of the next pass, or the operation repeats from its initial state forever. Symptom to recognise: a value that is correct within one pass and never accumulates across passes.

A guard asserting "the gap shrinks as you climb" was also simply wrong: the ladder doubles, so the gap resets at each rung. Hardening for an unreproduced bug is not free: it introduced a worse bug. - **A carry that lives in memory is a carry the next tick throws away.** The worst
  bug in the planet system's history, and the shape is worth recognising on sight.
  `productionRemainder` holds the sub-unit fraction of each tick so a track earning
  less than one unit per tick still banks something — necessary, because a Volcanic
  ore track peaks at 17.36/tick and a Glacial organics track at 0.17. It was a bare
  `= {}` with **no entry in `toJson`/`fromJson`**, and `GameTickService` re-parses
  the whole universe every pass, so each planet arrived with an empty map and
  `_drawProduction` computed `floor(0 + perTick)` forever.

  Measured across all 26 producible tracks: **13 banked exactly nothing**, the rest
  lost 6–37%, and at realistic staffing *no* world type banked a unit of organics or
  industrial — so no colony could self-supply even the level 1→2 requirement. The
  harsh-type design was erased along the way, because Terran produced zero organics
  too and the whole point of the five harsh types was that only they did.

  Three things about the failure are the transferable part:
  - **965 tests were green throughout.** Every production test held **one
    long-lived `Planet`** across all 2,880 ticks, which is precisely the condition
    under which the bug cannot appear. A guard that holds one object is testing a
    program the game does not run.
  - **The field's own doc comment described the bug it did not prevent** — "without
    it a colony producing 0.03/tick would bank nothing, ever". A comment explaining
    why a field exists is not evidence that it works.
  - **The displayed figure never consulted the carry.** The colony card reads the
    non-consuming getter, so it showed 2,142/day while the store never moved. A
    screen and a tick can agree perfectly on a formula and still disagree about
    reality if only one of them carries state between frames.
- **A per-instance mutable map cannot be a `const` default, and a mutable default
  *parameter* is not available either.** Dart requires default parameter values to
  be constant, so the fresh map has to be built in an **initializer list** — and a
  `fromJson` fallback of `const {}` hands the unmodifiable map straight back,
  defeating the initializer entirely. Both halves were wrong in the making of this
  fix, and the symptom (`Cannot modify unmodifiable map` on the first tick of every
  colony) is loud enough to find.
- **A guard that fails on correct code gets deleted, not fixed.** A "no drone
  workforce arm" check asserted the literal `case 'drones'` appeared nowhere in
  `planet_screen.dart`, and failed on two legitimate uses — the transfer switches
  over *stores*, where drones are a real storable commodity. Scoped to the one
  function instead, and comments stripped from both, because the comment left at the
  removed line **named the symbol it removed**.
- **An external review is a hypothesis with citations, not a diff \u2014 check its arithmetic too.** A review of `port.dart` correctly identified that `regen()` only sets the *rate* of refill and never the size of `maxSupply`/`maxDemand`, and correctly found that `changed` was set on \\"below the cap\\" rather than on \\"a stored integer moved\\". Both verified and fixed. Three things it got wrong or assumed: (a) it asked for **the per-`PortClass` supply/demand table**, which does not exist \u2014 there is one distribution, `CommodityConfig.qtyMin..qtyMax`, and every class draws from it identically, so hardware emporiums have *zero* demand; (b) it wanted to know whether `produce()` pauses offline, which it does \u2014 `Planet.produce` is tick-counted with no wall-clock catch-up, and the tick is a `Timer.periodic` that does not run while the app is closed; (c) it claimed the loose `changed` test meant the short-circuit \\"effectively never\\" fired, which is an overstatement \u2014 the rounding only zeroes for ~43s on a 1000-unit commodity and ~0.5s on an 80,000-unit one, so it is a real but small saving. **Write the guard against the boundary you actually measured, and say so in the comment**, because the first draft of it asserted a 10-minute tick rounds to zero and does not.
- **A wall-clock deadline is a deadline the player can walk away from.** The unifying
  rule is `GameClock`: one tick is 30 seconds, so 30 minutes is 60 ticks and a day is
  2,880, and **nothing in the game measures game time any other way**. Six mechanics
  were quietly on `DateTime.now()`, and every one had the same shape of bug — the
  game can be shut off, so a clock that keeps running hands out rewards and clears
  punishments for time nobody played:

  | what | the bug |
  |---|---|
  | Port refill | a sold-out market **restocked itself overnight** |
  | Bank interest | a player who slept a week got a week of interest; one who played seven hours got almost nothing |
  | Hack ban | **quitting cleared the ban** |
  | Sabotage | the 30-minute debuff expired during dinner |
  | Lottery limit | it lived in the widget's `State`, so **the limit reset every time you left the tab** — unlimited plays |
  | Bounty TTL | lapsed during a week the game was shut |

  Four properties, each of which was a bug first:
  - **The counter must be persisted.** A counter that reset on launch makes every
    stored "expires at tick N" meaningless (`N - 0` is enormous, so nothing ever
    expires), and the obvious repair — clamping a negative elapsed to zero — makes
    every cooldown *vacuous* instead. The ban is gone either way. A 60-tick save
    throttle is the deliberate trade: a crash rewinds at most 30 minutes, which is
    generous and **not farmable**, because restarting does not reset the counter.
  - **A per-tick rate needs a carried remainder, and the carry must be an integer.**
    2,880 ticks to full means one tick is `max / 2880` — 0.347 units for a 1,000-unit
    commodity, which truncates to nothing, so a small port would lose ~38% of its
    stock a day and effectively never restock. A `double` carry then made it worse in
    a way that was invisible: accumulated over 2,880 ticks it landed a 50,000-unit
    port on 49,999, permanently, since the port clamps at its cap. **A per-tick rule
    needs a per-tick test** — the first version of that test called
    `regenTick(ticks: 2880)` once instead of stepping 2,880 times, and passed against
    the faulty code.
  - **A tick deadline cannot be shown as a seconds clock.** It has 30-second
    resolution, so `23:58:31 → 23:58:30` would be inventing precision. Both countdowns
    render `GameClock.format` — `23h 58m` — and that is the honest answer.
  - **Re-stamping a clock on every event makes the rate depend on activity.** The old
    port field was refreshed by every trade, so a *busier* port refilled more slowly
    and a daily visitor's port starved relative to one nobody visited. An accumulator
    has no clock to reset, so this disappeared as a side effect rather than as a fix.
- **An override on the interval is not an override on the clock.** The Automation
  console changes how often the loop fires; it deliberately does **not** redefine how
  long a tick is worth. Otherwise every cooldown in the game silently shortens the
  moment somebody opens the dev console.
- **One clock for the whole economy, and the port side was the last holdout.**
  Port demand used to refill on **wall-clock** (`DateTime.now() - lastRegenTime`),
  so a sold-out market quietly restocked itself while the app was closed — the one
  part of the economy that paid the player for time they did not spend. Colony
  production was always tick-counted, so the two halves of one economy ran on
  different clocks. Fixed: `Port.regenTick(ticks)`, driven by `GameTickService` and
  by nothing else, and `lastRegenTime` is deleted so there is no parameter to
  pass wrongly.
  Three things that fix dragged out, none of which were obvious in advance:
  (1) **The old field was re-stamped by every trade**, so a port refilled faster
  the *less* it was visited — a daily visitor's port refilled more slowly than
  one nobody ever came to. An accumulator has no clock to reset, so this
  disappeared as a side effect rather than as a separate fix.
  (2) **A per-tick rate does not survive integer truncation.** `max / 2,880` is
  0.347 units for a 1,000-unit commodity, so a small port loses ~38% of its
  stock a day and effectively never restocks. The sub-unit remainder is carried
  per commodity.
  (3) **The carry must be an integer numerator, not a `double` fraction.** The
  `double` version accumulated over 2,880 ticks and landed a 50,000-unit port on
  **49,999** — and since the port clamps at its cap, that shortfall is permanent.
  A test asserting exact equality on a whole day is what caught it; the first
  attempt at that test passed against the faulty code, because the fixture ran
  one bulk tick instead of 2,880 individual ones. **A per-tick rule needs a
  per-tick test** — a single call with `ticks: 2880` does not accumulate the
  way 2,880 calls of one tick do.
  A measured note that survives: a median port absorbs ~83,700 units/day across
  all commodities (260 sampled ports, 22.97M/day galaxy-wide) against a fully-
  staffed Terran colony's 8,295/day, so any balance arithmetic on this economy
  has to state the fraction of the day the app is open.
